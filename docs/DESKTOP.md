# Модельная — установка, обновления и сохранение работы

Стабильный выпуск — 2.3.1. Эта ветка также содержит черновик 2.4.0: шестерёнку настроек, полный экран, перенос прежней папки и HTML с инструкцией. Внутри приложения **Проверить обновления** теперь находится в **Настройки приложения → Обновления и справка**; пункт меню окна остаётся доступным. Подробнее — в руководстве пользователя этой сборки.

## Установить приложение

Скачайте **ModelStudio-Setup-2.3.1-x64.exe** из [выпусков проекта](https://github.com/sashasychev05-sketch/model-studio/releases/latest) и запустите его. Установщик на русском языке создаёт ярлыки для текущего пользователя; права администратора не нужны. Программа открывается отдельным окном. При первом переходе с ZIP-сборки библиотека подхватится из прежнего каталога **%APPDATA%/Модельная/library**.

## Обновить установленное приложение

Откройте **Настройки приложения → Проверить обновления**, либо выберите **Приложение → Проверить обновления** в меню окна. В стабильной версии 2.3.1 эта кнопка находится в каталоге. Если вышла новая стабильная версия, подтвердите скачивание. После загрузки выберите **Установить и перезапустить** или **Продолжить работу**. Обычное закрытие приложения не устанавливает отложенное обновление.

Несохранённая модель или анализ блокируют установку: сохраните работу либо отмените правки и повторно нажмите кнопку обновления. Уже скачанный файл используется повторно. После установки приложение открывается снова; сохранённая библиотека не заменяется.

При запуске установленной версии проверка выполняется один раз в фоне: меняется подпись кнопки, но скачивание и установка не начинаются без согласия. Для проверки и загрузки нужен интернет. Работа с моделями и HTML-опытами остаётся доступной без интернета.

ZIP-сборка и исходники не заменяются автоматически: сначала установите NSIS-версию. Будущие выпуски загружаются через HTTPS из этого публичного репозитория. electron-updater проверяет SHA-512; повреждённый файл не устанавливается. **Сертификат Windows пока не подключён: этот установщик не подписан, а SHA-512 не подтверждает личность издателя.** Windows может показать предупреждение. Когда появится сертификат, подписанные сборки будут включать проверку издателя последующих обновлений.

## Запуск Windows-сборки

Распакуйте ZIP целиком в обычную папку и откройте **ModelStudio.exe**. Не переносите exe отдельно от остальных файлов. Устанавливать Node.js, открывать браузер или держать терминал не нужно. Приложение работает без интернета.

Библиотека хранится в каталоге пользовательских данных приложения: **%APPDATA%/Модельная/library**. Замена папки программы новой сборкой не меняет библиотеку. Для резервного хранения используйте кнопку **Резервная копия** в каталоге.

Это Windows x64-сборка без цифровой подписи. Проверки на macOS/Linux для отдельного окна не выполнялись.

## Передать опыт ученику

Откройте модель → **Экспорт → Готовая демонстрация · HTML**. Передайте полученный файл ученику. Он открывается обычным двойным щелчком в современном браузере, без приложения, Node.js, сервера и интернета. Поддерживаются и сцены конструктора, и HTML-модели. JSON остаётся редактируемым форматом обмена.

## Сохранить самостоятельный анализ

В каталоге откройте **Анализ данных**, загрузите таблицу или выберите пример. Нажмите **Сохранить анализ** (либо Ctrl+S). Таблица, единицы колонок, выбранные оси, вид графика и фиксированные области сохраняются в библиотеке. После повторного открытия нажмите **Рассчитать статистику и график**: результаты пересчитываются из сохранённых исходных данных.

Сохранение явное. Закрытие окна с изменённым самостоятельным анализом вызывает предупреждение. Возврат в каталог сохраняет рабочий сеанс до закрытия приложения. Несохранённый импорт и предпросмотр не входят в сохранённую таблицу.

Запись защищена ревизией: второе окно не может молча заменить более новый анализ. При конфликте экспортируйте свой JSON, затем откройте сохранённую версию.

## Резервная копия и восстановление

**Резервная копия → Скачать резервную копию** сохраняет один JSON с папками, моделями (включая корзину), историей версий и сохранённым самостоятельным анализом. В копию не входят браузерные черновики, темы и размеры панелей. Сначала сохраняйте нужные правки.

Для восстановления выберите **Открыть резервную копию**. Приложение проверяет структуру, ссылки, формулы и данные, затем показывает состав копии. Поставьте флажок замены библиотеки и нажмите **Восстановить**.

Перед заменой прежний каталог сохраняется рядом с библиотекой под именем **library.before-…** (в исходной версии — **data.before-…**). Путь доступен после восстановления. Возврат к прежней библиотеке: скопируйте эту папку в отдельный каталог, запустите исходную версию с MODEL_STUDIO_DATA_DIR, скачайте её резервную копию и восстановите через интерфейс приложения.

Восстановление получает новые ревизии, поэтому старые черновики не перезаписывают восстановленные модели. При сбое между сменой каталогов следующий запуск возвращает прежнюю библиотеку. Смена библиотеки после предпросмотра требует нового предпросмотра.

Лимиты: 128 MiB для файла копии, 500 моделей, 500 папок, до 30 предыдущих версий одной модели. Научные лимиты таблиц остаются прежними.

## Перенос из прежней версии

Старую папку data не удаляйте. В обновлённой исходной версии, запущенной с прежней папкой data, скачайте резервную копию. Откройте новую Windows-сборку и восстановите эту копию. Новое приложение не переносит и не перезаписывает старую библиотеку автоматически.

## Для разработчика

Исходный запуск в браузере по-прежнему доступен: node server.mjs или ЗАПУСТИТЬ-В-БРАУЗЕРЕ.cmd. Для отдельного окна и сборки нужны зависимости:

```sh
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm desktop
pnpm package:desktop
```

Сборка находится в dist/ModelStudio-win32-x64. Только публичные gallery, web, lib, desktop и сервер попадают в app.asar; пользовательские данные, рабочие каталоги, тесты и node_modules исключены. Electron и его уведомления лицензий поставляются в сборке.

```sh
node --test tools/*.test.mjs
node tools/check-gallery.mjs
pnpm exec playwright install chromium
pnpm test:browser
pnpm test:desktop
```

CI запускает Node-проверки и Chromium на Windows/Linux, затем проверяет исходное окно, ZIP/NSIS-сборки, реальную загрузку с проверкой повреждённого файла и установку/переустановку на изолированном Windows runner. Сохраняются ZIP и установщик с latest.yml и blockmap. При публикации тега версии CI после успешных проверок публикует выпуск GitHub; скачивание и установка на компьютере пользователя требуют его подтверждения.

## Выпустить следующую версию

Обновите version в package.json, строку версии в web/app.js и release в server.mjs, опишите изменения и пересоберите руководство. Прежде чем менять формат библиотеки, добавьте совместимый перенос и проверку старых данных. Не изменяйте appId, имя Модельная и каталог userData: они связывают версии программы и библиотеку.

```sh
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm package:installer
```

Локальный результат — dist/installer/ModelStudio-Setup-VERSION-x64.exe, latest.yml и blockmap. Для длинных путей Windows используйте короткий путь checkout: NSIS не читает include-файлы с путями длиннее 260 символов. Установщик не включает пользовательские данные; electron-updater и его лицензии собраны в отдельный runtime без дерева node_modules.

После сохранения и отправки изменений создайте тег **vVERSION**, совпадающий с package.json, и отправьте его в GitHub. Workflow check.yml проверит код, установщик и сохранность библиотеки, затем опубликует выпуск. Неверный тег, несовпадающие размер/хеш установщика и попытка опубликовать старую версию отклоняются. До загрузки всех файлов выпуск остаётся черновиком. Читатели приложения не получают GitHub-токен; GITHUB_TOKEN используется только в CI для публикации.

Для подписи настройте секреты репозитория **WINDOWS_CSC_LINK** (сертификат, поддерживаемый electron-builder) и **WINDOWS_CSC_KEY_PASSWORD**, затем переменную **WINDOWS_REQUIRE_SIGNING=1**. При обязательной подписи сборка без сертификата завершается ошибкой. Ключи и пароли не добавляются в исходники и сборку. Для аппаратного ключа или облачного сервиса требуется настройка соответствующего провайдера подписи electron-builder.

MODEL_STUDIO_TEST_BUILD_VERSION используется только для отдельного установщика-предшественника в dist/installer-fixture; его файлы не публикуются. MODEL_STUDIO_INSTALLER_TEST=1 включается только на одноразовом CI runner: этот тест регистрирует приложение в Windows и запускает деинсталлятор. Обычные локальные desktop-тесты регистрацию Windows не меняют.

Окно не предоставляет модели доступ к Node.js: sandbox и contextIsolation включены, nodeIntegration выключен. Произвольная навигация и новые внешние окна блокируются; локальное руководство открывается внутри приложения. Сервер слушает только loopback, завершает работу при закрытии приложения. HTML-изоляция и автономный экспорт сохранены.
